Evidence-carrying files are owner-only wherever they are written. `research.db` was hardened at 0600 only when a private corpus was in the report, so an ordinary `--store` or discovery-queue run left the database and its WAL sidecars group-readable while `SECURITY.md` documented 0600; the hardening now happens in `store.init_db`, the choke point every database entry goes through. The discovery nominations bundle and the leg-2 pending report were written with default permissions despite embedding full `SourceItem` bodies (including private corpus text), and now use the same 0600 write path as `last-run.json`.
