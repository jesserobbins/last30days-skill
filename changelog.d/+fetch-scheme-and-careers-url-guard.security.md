The HTTP seam refuses non-HTTP(S) URLs, and the `--hiring-signals` careers probe refuses search results that point at the local network. The shared opener also handles `file://`, `ftp://`, and `data://`, so a URL that reached the engine from outside could read a local file and return it as a fetched page; the scheme is now checked before a request is built. The careers probe accepted the first search hit containing a careers-ish token, which made a poisoned or SEO'd result a request-forgery primitive against link-local metadata and internal admin pages — literal addresses and local hostnames are now rejected before anything is fetched.

The careers guard now holds across the whole request, not just its first hop: redirect targets must stay HTTP(S) and must satisfy the same public-address rule, the guessed `{slug}.com`/`.ai`/`.io` candidates are covered as well as search results, addresses must be globally reachable (the earlier "not private" test admitted the carrier-grade NAT range that holds Alibaba Cloud's metadata endpoint), scoped IPv6 literals and non-canonical numeric hosts like `127.1` are rejected, and a hostname whose DNS record points at a private address is refused.

A validated name is not a validated connection: the lookup that clears a URL and the lookup `http.client` performs when it connects are separate, so a rebinding zone could answer publicly first and with a loopback address for the real connection. Requests that carry the careers rule now connect only to an address resolved and approved at connect time, with the original hostname still driving the `Host` header and TLS SNI; a proxied environment cannot pin the socket and keeps the validated-name behaviour.
